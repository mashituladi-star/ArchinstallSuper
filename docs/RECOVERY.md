# Восстановление после сбоя

Установщик старается оставить систему в предсказуемом состоянии, но при
отключении питания, ошибке pacstrap или сбое диска может потребоваться ручное
вмешательство. **Не запускай установку повторно вслепую.**

## 1. Понять, что успело произойти

```bash
lsblk -f
findmnt -R /mnt || true
cryptsetup status cryptroot 2>/dev/null || true
```

Журнал установщика:

```text
/var/log/archinstallsuper.log
```

Если целевая система уже смонтирована, копия журнала может быть в
`/mnt/var/log/archinstallsuper-install.log`.

## 2. Размонтировать целевую систему

```bash
umount -R /mnt
```

Если `umount` жалуется на занятость:

```bash
findmnt -R /mnt
lsof +D /mnt 2>/dev/null || true
```

Не используй `umount -l` без понимания последствий: ленивое размонтирование
может скрыть незавершённую запись.

## 3. Закрыть LUKS

Только после успешного размонтирования:

```bash
cryptsetup status cryptroot
cryptsetup close cryptroot
```

Если контейнер занят, сначала найди, что его держит:

```bash
findmnt | grep mapper
```

## 4. Оценить состояние диска

```bash
lsblk -f
blkid
```

Варианты:

- **Диск ещё не размечался.** Можно просто запустить установщик снова.
- **Разметка и ФС созданы, pacstrap не завершён.** Проще начать заново: диск
  всё равно будет очищен.
- **Установка почти завершена, но загрузчик не установлен.** Можно попробовать
  войти в live-среду, смонтировать разделы и выполнить `arch-chroot`, но это
  требует понимания текущей разметки. Если сомневаешься — переустанови.

## 5. Если система установлена, но не загружается

Проверь в live-среде:

```bash
lsblk -f
mount /dev/<root> /mnt          # для LUKS: cryptsetup open ... && mount /dev/mapper/... /mnt
mount /dev/<efi> /mnt/boot
arch-chroot /mnt
bootctl status
cat /boot/loader/entries/archinstall-super.conf
cat /proc/cmdline
```

Типичные причины:

- **Btrfs:** в загрузочной записи нет `rootflags=subvol=@` или в fstab нет
  `subvol=/@`.
- **LUKS:** нет hook `encrypt` в `/etc/mkinitcpio.conf`, неверный `cryptdevice`
  UUID или неверный `root=/dev/mapper/cryptroot`.
- **Secure Boot:** systemd-boot не подписан; нужно отключить Secure Boot или
  добавить ключи вручную.
- **Не тот диск:** проверь UUID в fstab и в загрузочной записи.

Пересобрать initramfs:

```bash
arch-chroot /mnt mkinitcpio -P
```

Переустановить systemd-boot:

```bash
arch-chroot /mnt bootctl --esp-path=/boot install
```

## 6. Блокировка установщика

Если установщик пишет, что другой экземпляр уже работает:

```bash
cat /run/archinstallsuper/installer.lock
```

Убедись, что процесс действительно не запущен, затем удали lock-файл:

```bash
rm -f /run/archinstallsuper/installer.lock
```

Не удаляй lock, пока установка реально идёт.

## 7. Когда лучше переустановить

Переустановка с нуля безопаснее, если:

- диск был частично размечен и ты не уверен в состоянии ФС;
- pacstrap прервался на середине;
- неизвестно, какие пароли и UUID были использованы;
- есть сомнения в выбранном диске.

Установщик всё равно стирает весь диск, поэтому «ремонт» частичной установки
обычно не даёт преимуществ.

## 8. Что не делает установщик

- Не делает резервные копии.
- Не восстанавливает данные после `wipefs`/`sgdisk`.
- Не подписывает загрузчик для Secure Boot.
- Не настраивает TPM/FIDO2 для LUKS.
- Не умеет ручную разметку и сохранение других ОС.

Если данные на диске нужны — остановись и используй специализированные
инструменты восстановления, а не повторную установку.
